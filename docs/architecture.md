# 雅睿英语技术架构

## 1. 目标与约束

本架构服务于当前 M0 最小纵向闭环，同时给 M1 的真实后端保留稳定替换点。首要目标是让跨教师、学生、家长的同一任务数据保持一致，并能低成本演示成功、失败、空数据和无权限状态。

约束如下：

- 保留现有微信原生小程序工程，使用 TypeScript、WXML、Less。
- M0 只使用本地模拟数据，不连接云数据库、AI、音视频或通知服务。
- M0 不使用第三方状态管理，不提前建设通用平台或管理后台。
- M1 后端优先采用 CloudBase；所有敏感凭据只存在服务端。
- 当前工程不修改既有模板页面和路由；页面开发由后续实现任务完成。

## 2. 分层结构

```text
WXML / Less / 微信原生组件
          │
页面控制器（输入、反馈、页面级状态、导航）
          │
应用服务（用例编排、权限上下文、错误映射）
          │
纯领域模块（状态流转、校验、统计、快照规则）
          │
Repository 接口（稳定的数据访问边界）
          │
M0 内存模拟实现 ───────── M1 CloudBase 云函数适配器
```

### 页面层

页面只处理微信生命周期、用户输入、加载/空/失败反馈和导航。页面不得直接引用 `mocks/`，不得在多个页面复制业务规则，也不得以隐藏按钮替代权限校验。

### 应用服务层

每个服务围绕用户意图组织，例如登录、发布任务、提交作业、发布点评、读取孩子结果。服务接收显式 `RequestContext`，调用领域规则和 repository，并返回统一结果结构。

### 领域层

纯 TypeScript 函数负责：任务字段校验、生命周期流转、学生任务关系流转、提交版本递增、完成统计、点评发布条件和只读权限判断。此层不调用 `wx` API，便于 Vitest 快速测试。

### Repository 层

Repository 隐藏数据来源。M0 实现维护单一内存状态树并返回深拷贝；M1 实现调用按业务边界划分的云函数。页面和领域模型不感知底层切换。

## 3. 建议的后续源码组织

以下目录在实现 M0 页面时按需创建，本基础任务不预建空目录：

```text
workspace/miniprogram/
├─ pages/                  # 按角色和页面语义组织
├─ components/             # 跨页面复用的展示组件
├─ domain/                 # 纯类型、规则、状态机、统计
├─ services/               # 用例级接口与应用服务
├─ repositories/           # repository 接口及实现选择
│  ├─ memory/              # M0 内存实现
│  └─ cloudbase/           # M1 云函数适配器
├─ mocks/                  # 统一虚构数据和场景定义
├─ session/                # 当前账号、角色和导航所需少量会话状态
└─ shared/                 # 通用 Result、时间、标识等小型基础模块
```

依赖方向必须自上而下：页面可依赖 services；services 可依赖 domain 和 repository 接口；repository 实现可依赖 domain；domain 不依赖页面、微信 API 或具体数据源。

## 4. M0 运行时设计

### 单一数据源

应用启动时由 `MockScenarioRepository` 载入选定场景，生成账号、角色、班级、任务、学生任务关系、提交和反馈。三个角色读取同一个内存状态树，因此教师发布、学生提交和教师点评会立刻反映在家长查询中。

页面切换不重建 repository。主动重置场景或小程序冷启动才恢复种子数据。实现时可选用内存快照加微信本地缓存以支持开发者工具刷新；缓存只存虚构数据，并带 `schemaVersion`，版本不匹配时安全重置。

### 状态管理

- `App.globalData` 只保存当前会话标识、角色和 service 容器引用。
- 页面表单、筛选、加载和错误状态放在当前页面 `data` 中。
- 领域实体不复制到全局可变状态；每次通过 service 查询或提交 command。
- service 对外返回新对象，防止页面 `setData` 引用意外修改存储。

### 场景与错误注入

模拟层提供至少：正常、空数据、网络失败、无权限、提交失败、点评失败、资源下架、已过期。错误注入按下一次调用或指定方法生效，不能把失败分支硬编码到页面。

## 5. M1 演进

M1 保留页面、应用服务调用方式和领域类型，替换 repository 工厂：

| M0 | M1 |
| --- | --- |
| 内存账号和角色 | 云函数换取业务会话并查询授权角色 |
| 内存状态树 | 云数据库集合与服务端事务 |
| 本地权限判断 | 前端预检查 + 云函数强制授权 |
| 本地任务快照 | 服务端生成不可变任务快照 |
| 本地提交版本 | 服务端原子递增版本并保留历史 |
| 模拟错误 | 标准化云函数错误映射 |

建议按业务能力划分云函数入口，如 `auth-session`、`task-command`、`task-query`、`submission-command`、`review-command`、`parent-query`，而不是每个数据库集合一个云函数。跨集合写入使用服务端事务；客户端永远不持有数据库管理权限。

云存储在 M1 只用于当前里程碑确实需要的文件；录音、AI 和媒体处理属于后续里程碑。生产密钥通过服务端环境变量或密钥管理配置，禁止进入小程序包。

## 6. 管理后台边界

独立管理后台在后续阶段使用 React + TypeScript + Vite，通过与小程序相同的业务 API/云函数边界访问数据，但拥有独立身份、权限和部署。M0 不创建后台目录、不把后台管理员塞入小程序身份选择，也不为未实现后台增加依赖。

## 7. 关键技术决策与取舍

| 决策 | 选择 | 原因与代价 |
| --- | --- | --- |
| 小程序框架 | 微信原生 | 与既有工程和官方能力直接兼容；复用仅限微信端，但当前没有跨端需求 |
| M0 数据 | 内存 repository + 场景种子 | 反馈快、无需账号和后端；刷新/冷启动默认重置，不代表持久化能力 |
| 状态管理 | 页面局部状态 + 小型 session service | 依赖少、心智负担低；复杂跨页状态必须走 repository，不能任意全局共享 |
| API 边界 | 应用 service + repository | M1 可替换且便于测试；需要约束页面不得绕过边界 |
| 测试 | TypeScript + Vitest | 领域规则可快速回归；微信渲染和设备能力仍需开发者工具与真机验证 |
| 后端 | CloudBase | 微信生态集成和运维成本低；通过接口和领域模型隔离供应商特性 |
| 管理后台 | React + TypeScript + Vite（后续） | 独立部署和信息密度更合适；当前不提前建设 |

## 8. 非功能边界

- 所有写操作必须可重试并避免重复提交；M1 使用 `operationId` 或等价幂等键。
- 日志只记录匿名标识、操作、结果和错误码，不记录密码、手机号、题目正文、录音或点评正文。
- 删除策略默认为软删除/状态关闭；历史任务、提交和反馈不可被资源更新覆盖。
- 页面加载失败保留现有内容和输入；网络恢复后由用户重试或页面重新查询。
- M0 验收聚焦竖屏主路径；横竖屏连续性、防快进和媒体弱网恢复留到权威里程碑。
