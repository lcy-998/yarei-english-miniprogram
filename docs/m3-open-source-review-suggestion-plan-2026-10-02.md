# M3 教师点评建议开源试验计划（2026-10-02）

> 状态：Qwen3-0.6B 已作为 M3 教师 AI 建议的首个本地试验候选纳入 0.58.0 基线；云端可行性、质量与验收均待实测，不构成 M3 开工或部署授权。M2 仍在开发中。此方案只处理 T-08 的教师点评**建议草稿**，不替代人工评分、正式点评发布或 Vosk 跟读评分。

## 1. 试验目标与候选

- 候选为 **Qwen3-0.6B 的固定量化 GGUF + llama.cpp CPU 推理**。Qwen3 模型许可为 Apache 2.0；候选 `Q4_0` GGUF 文件约 429 MB。只在本地取一次模型，记录来源版本、许可证、SHA-256 和推理程序版本；运行时不得访问外部模型 API 或下载模型。
- 目标是从**当前正式提交版本及发布快照中可核对的证据**生成 50—150 字中文建议。输出必须是建议草稿，教师可采纳、编辑、重新生成或放弃；最多重新生成 3 次，教师点击正式发布前学生和家长不可见。人工点评在模型不可用时继续可用。
- 候选模型体积已接近普通云函数单版本代码包 500 MB 限制。CloudBase 云托管要求开启超限按量，不符合本轮“无新增费用”的试验目标。因此必须先证明普通云函数包体、内存、冷启动、生成时延、质量及套餐内用量均可行；**此处不是部署成功或零费用承诺**。
- 用简单、可审计的规则生成“常用评语推荐”作为独立回退。规则推荐不能标为 AI 点评，也不算 TCH-007 的 AI 建议切片通过。若小模型无法过门槛，停在该状态并提交替代方案，不擅自购买算力或改动验收口径。

## 2. 可信数据流

```text
教师 T-08 点击“AI 点评”
  → 现有 review-query 授权读取当前正式提交与发布快照
  → 服务端最小证据摘要、教师选定评价维度、版本校验
  → 独立受限推理适配器生成候选
  → 服务端事实/长度/敏感内容校验并保存建议版本
  → T-08 显示草稿；教师采纳、编辑或放弃
  → 现有 review-command 经教师二次确认发布正式反馈
```

- **可信输入**：服务端按当前教师与班级授权取得任务、学员任务关系、正式提交版本和冻结内容快照，抽取必要的题目类型、正确/待人工评分数量、阅读范围完成证据、单词首次作答与跟读有效分等。未记录的证据显式标记“未记录”，不把学生答案中的文字当作系统指令。默认不传姓名、手机号、学号、录音原文或无关个人资料。
- **输出契约**：模型仅返回结构化 `suggestionText`、引用的证据 ID、生成版本。服务端验证 50—150 个中文字符范围、引用只来自当前证据、没有虚构分数/作答、无敏感信息和越界建议；失败即不给教师展示模型文本，保留人工点评输入。
- **提示约束**：要求正向、具体、可执行，不诊断学生能力或健康、不比较其他学员、不承诺未经记录的学习表现。固定非思考模式、输出长度上限和低随机性；学生作答与评语候选均作为不可信数据处理。提示词与模型版本留存于服务端，不写入小程序源码。
- **重试与审计**：同一教师、提交 ID/版本、评价维度及操作 ID 的重试返回同一建议；重新生成最多 3 次，每次形成独立候选与版本。生成、拒绝、采纳、编辑、放弃和正式发布有脱敏审计；提交版本、教师权限或评分草稿变化后旧建议失效。正式反馈记录人工发布者和 AI 辅助标识，不能自动发布或覆盖既有点评。
- **批量点评边界**：建议只针对当前学员的当前提交。教师若把文字用于既有一键点评，仍须经过原有预览令牌、影响人数核对与二次确认，不能将某名学生的个性化证据或建议自动套用给其他学员。

## 3. 分阶段工作与停止点

| 阶段 | 要完成的工作 | 退出或停止条件 |
| --- | --- | --- |
| P0 规格与样本 | 固定上述输入/输出合约；从统一虚构演示数据制作不少于 100 个提交场景：全对、部分错、漏答、无证据、待人工分、退回重做、跨版本、恶意文本和敏感内容。两位评审独立标注可用建议及必须拒绝情形。 | 样本不含真实未成年人资料；事实字段都能从现有提交/发布快照核对。 |
| P1 本地小模型试验 | 固定 Qwen3 0.6B、量化文件及 llama.cpp 版本，在与 CloudBase 相同的 Linux 架构打包；测模型加载、内存、冷/热请求、100 个样本的中文输出与事实约束。 | 包体超过目标普通函数限制、内存不足、生成太慢或事实错误不可控时停止云端准备。不得自动转用云托管。 |
| P2 服务端合约 | 在现有 service/repository 后加入建议服务和可替换推理端口；严格鉴权、脱敏证据摘要、幂等/三次重生、版本失效、敏感内容拒绝与审计。正式发布仍走现有 review-command。 | 本地单测和合约测试覆盖越权、提示注入、虚构事实、重复操作、教师修改及发布失败输入保留。 |
| P3 小程序交互 | T-08 显示“生成中”、建议、采纳/编辑/重新生成/放弃以及失败回到人工点评；切换任务、学员或提交版本时保护未发布输入。 | 建议不自动写正式反馈；所有人工分和评语由教师最终确认。视觉状态先审批再修改 WXML/Less。 |
| P4 非生产部署试验 | M2 退出后按 M3 具体审阅包核对环境、额度、安全规则与回退版本，只对虚构账号限量开放普通云函数；先测内部推理，再接 T-08。 | 无新增费用、客户端不能直调推理、跨组织/撤权请求拒绝、函数可回退。若平台要求付费能力则停止。 |
| P5 质量与使用验收 | 用冻结的虚构评测集及人工双评复核事实正确性、内容安全、50—150 字格式、三次重新生成的差异、教师采纳/编辑率，记录冷/热生成时延与实际资源点消耗。 | 数值门槛须在正式测试前确认；未达标则仅保留人工点评及规则推荐，不标记 M3 AI 点评通过。 |

## 4. 本地试验的建议门槛（尚非正式验收）

1. **事实与权限优先**：在冻结的 100 个虚构场景中不得出现跨学生/班级泄露、伪造分数、伪造作答或自动发布；敏感/恶意输入必须被阻断或降级到人工点评。
2. **教师可用性**：两位评审记录“可直接采纳、编辑后可用、不可用”，同时统计平均编辑量；正式可用率门槛待看到基线分布后冻结，不用只看模型自评。
3. **性能与费用**：建议先以冷/热请求的 P95、单次资源点和一个月预计调用量评审；可把 P95 ≤20 秒作为候选体验目标，但不是当前产品已确认指标。普通函数的目标代码包须低于平台限制并留合理余量；当前约 429 MB 的模型意味着打包超限风险较高。
4. **隔离失败**：超时、空输出、中文长度不合规、敏感内容或事实校验失败时显示可执行的重试/人工点评，不扣掉已有输入，不发布、不生成虚假的 AI 辅助标识。

## 5. 后续需确定的范围

- 用户是否接受以小模型的人工双评结果作为 M3 教师 AI 点评质量依据，以及正式可用率/时延门槛；本计划不自行改变原有 50—150 字、三次重生和人工确认口径。
- 如果普通云函数无法容纳模型或套餐内用量不足，是否继续保持“人工点评 + 规则推荐”，或另行评审有费用的自托管计算。不得将规则推荐冒称为 AI，也不得在本次试验中开通付费。
- 任何真实学生作答、姓名或录音进入模型前需独立审阅未成年人数据最小化与生产门禁。本次只做虚构非生产样本。
