# M2 A-07 任务与活动管理本地实现

本切片遵循当前 0.27.0 权威文档。只使用虚构数据；云函数已部署到非生产环境，A-07 列表和详情的后台令牌读取通过，浏览器页面人工验收仍缺证据。

## 范围与口径

- 左侧“任务与活动管理”和 A-01 “任务与活动”卡片进入 A-07。列表区分课堂任务、打卡活动、任务模板；默认全部类型/状态、近 30 天、空关键词。时间范围按任务开始日、活动起始日、模板创建日筛选，最多 366 天。查询最多每页 100 条，界面每次加载 25 条。
- 课堂任务完成数取已发布任务关系中 `completed` 或 `awaiting_review` 的数量，待检查数取 `awaiting_review` 数量；待点评数为上述记录中尚无已发布反馈的数量。总数取已保存的学员任务关系，不从任务目标人数猜测。详情显示每名学员的当前状态、提交时间和实际评分。
- 打卡活动参与数取发布时保存的参与名单。仅有正式最终榜单快照时显示“全周期完成”的人数及完成率；运行中缺少完整结算证据时显示“未记录”。详情展示参与学员和已结算天数。
- 模板不产生学生提交，也无完成率或点评数；相关指标留空。M2 不生成 AI 辅助点评，标识为“否”。发布未完成、已发布但无任务关系、无参与学员和空模板等有来源的异常显示原因。
- 当前筛选 CSV 在服务端按同一授权和筛选口径重新查询后生成，仅含列表已有字段；超过 2000 行须缩小筛选。CSV 对电子表格公式前缀转义。管理后台通过浏览器下载 CSV 文件。

## 权限、停用与审计

- 新增 `admin-task-activity-query` 与 `admin-task-activity-command` 函数，仅接受 `admin-console` 会话。服务端要求可信 `admin` 角色及当前组织范围，读取需 `organization.read`，停用还需 `organization.manage`。小程序会话和教师角色均不能调用。
- 停用须由管理员二次确认、填写 1—200 字原因，并携带对象当前版本及唯一操作标识。待开始课堂任务转为已撤回；草稿、进行中和已过期课堂任务转为已关闭；草稿或已发布打卡活动转为已关闭；有效模板转为已删除。已结束/已停用项不可再次停用。提交、反馈和历史快照保留。
- 记录更新、幂等收据和成功操作审计在同一文档事务完成；版本冲突和数据库失败不改页面原列表。详情、筛选与导出失败均显示错误并可重试。
- 打卡活动文档同时保存顶层查询字段与完整 `payload` 快照。管理员停用在同一事务同步更新两处状态、版本及关闭时间；若原记录两处不一致则拒绝写入，避免教师、学生与定时维护无法再读取该活动。已发布活动的每日实例和参与名单保持原快照。
- 内存模式的三条虚构记录具备关联的虚构提交事件，课堂任务比例由该事件计算；打卡活动尚无最终结算快照，完成率保持“未记录”。内存模式仅展示与导出，停用按钮禁用，服务直接返回 `SERVICE_UNAVAILABLE`，不会把演示写入显示为正式成功。
