# M2 课堂任务再次布置快照合约

T-07 的“再次布置”经 `task-command.copyTaskSnapshot` 创建服务端持有的新草稿。请求只包含 `sourceTaskId`，并在请求顶层传入原任务当前 `expectedVersion` 和可重试的 `operationId`；客户端不能上传页图、题干或答案正文作为复制来源。

服务端重新校验教师仍有原任务班级的发布与内容权限、原资源仍上架且类型未变，再复制发布时冻结的内容、规则、版本、说明和可复用字段。新草稿有独立任务 ID，清空布置对象、开始/截止时间、提交、点评及发布记录；来源 ID 仅在服务端作为 `copiedFromTaskId` 保存。缺少指定阅读页图、结构化题干/答案或无法在 M2 表单保真的旧规则时明确拒绝，不从当前资源重新生成一个看似相同的副本。

T-06 打开复制草稿后，要求教师重新选择对象和时间。未改变的内容项连同原 ID、资源 ID、顺序、完成规则和计分规则原样保存；服务端仍以原快照发布，同时再次核验当前资源状态与目标班级权限。改动某项规则或内容时，该项按当前已授权资源重新冻结。分批发布完成前学生不可见；重新调用同一 `operationId` 不创建第二份草稿。

本地已覆盖原资源换图后快照保留、下架拒绝、旧规则拒绝、68 人分批发布和客户端请求字段。函数已部署到非生产云端，模板实例化与 500 人分批发布/中途不可见验证通过；再次布置页面操作及资源版本变更后的云端联调尚未执行。
