# M2 学生原始录音保留与清理（本地实现）

依据 `product-requirements-core.md` 0.28.0：学生原始录音自正式提交起保留 180 天，到期自动清理不进入 7 天恢复期；任务提交、评分与点评历史长期保留。S-12 用户主动删除未提交草稿的 7 天恢复规则独立适用。本文件描述本地服务端实现，不授权云存储删除、规则发布或部署。

## 已接入的本地边界

- `MediaRetentionService` 只扫描 `student_works` 和 `task_recordings` 中已封存、已提交且距 `submittedAt` 满 180 × 24 小时的记录。当前版本没有学校自然日的录音保留口径；时间使用服务端 UTC 时间戳。
- 仅对当前 CloudBase 环境下、与组织及学生摘要、记录 ID、SHA-256 完全匹配的私有 MP3 建立确定性清理计划。客户端传入的文件 ID、staging 路径、草稿、演示/教学音频、其他组织的文件均不能成为清理对象。
- 执行前重新读取源记录并核验文件引用；计划、认领、失败与完成状态保存在 `media_retention_jobs`。存储删除返回 `not_found` 视为中断后的幂等重试；同时写入 `mediaDeletedAt` 和操作审计。原提交、作品、成绩、点评、内容快照及只读元数据不删除，历史展示可用 `mediaDeletedAt` 标注“录音已过保留期”。
- 自 `submittedAt` 满 180 天起，学生作品和课堂录音的服务端临时试听地址立即拒绝发放，即使物理清理尚未跑到该文件；查询返回 `mediaExpired` 供历史页禁用试听。已发出的短期链接不能即时撤销，仍须在云端验证存储侧过期行为。
- S-12 已软删除草稿的暂存 MP3 由独立 `DraftStagingRetentionService` 处理：只有 `deletedAt`、本人删除记录及 `recoverableUntil` 均可信，且已满至少 7 × 24 小时并越过恢复截止时间，才建立计划。路径从组织、学生摘要和作品 ID 重新推导；执行前再核对未提交、仍已删除、同一版本和路径，并用版本锁阻止旧版本恢复操作与清理同时成功。删除结果、失败重试和审计与正式录音分开记录。未删除草稿和仍在 7 天恢复期的文件不会被清理。
- 其他未软删除的 staging 草稿仍无可信上传心跳或重试窗口；为避免误删仍在重试的学生录音，本次不做普遍的短期暂存清理。需另立活跃租约和失败恢复策略后实施。

## 部署前门禁

- 当前只有抽象删除端口与 FakeDB/存储替身测试，没有接真实 CloudBase `deleteFile`，也未将两类清理服务加入定时函数。草稿仅保存 `stagingPath` 而未保存完整 CloudBase file ID；未来云存储适配器必须按受控环境/桶配置解析路径，不能让客户端指定桶或文件 ID。原始录音到期不进入恢复期的口径已确认；真实云删除仍须验证存储 API 的 `not_found` 语义、环境 ID 与桶后缀、分页吞吐和并发恢复，再按已确认的非生产范围执行并记录结果。
- `media_retention_jobs` 已列入本地 M2 数据库清单，要求服务端独占访问；集合及索引尚未在云端创建。
- 2026-09-29 用户确认：正式提交的学生原始录音满 180 天后自动到期清理，不再进入 7 天恢复期。当前本地服务可在到期后删除替身对象；真实云存储清理、短期试听地址到期和审计仍需按上条门禁联调，不能把本地测试计作云端通过。
- S-12 草稿清理遵守已写入记录的 7 天 `recoverableUntil`。用户已确认由 A-03 后台管理员按记录恢复；本地恢复服务及页面已接入，截止时间、作品版本和 `stagingCleanupStatus` 阻止清理锁定后的恢复。真实云存储、管理员赋权与后台人工验收仍未执行，不能把本地逻辑当作完整恢复验收。
- 扫描器需要按组织与两类源集合逐页调用 `planBatch`，再按 `media_retention_jobs` 执行计划。真实定时接入、断点游标、限流与监控尚未完成；本地测试不代表自动清理已上线。
