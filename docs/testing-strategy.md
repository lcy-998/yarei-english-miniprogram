# 测试策略

> M1 于 2026-09-25、M2 于 2026-10-02 分别经用户明确批准开发交付验收；未执行的页面、媒体、真实 Timer、满证据容量、真机和弱网/安全仍须按实际证据追踪。M3 未开始；A-01—A-08 的原生小程序迁移已规划到 M3，现有网页后台证据不算原生验收。阶段现状见 `DOCUMENTATION.md` 与 `docs/reviews/m2-final-acceptance-2026-10-02.md`。本文件中的检查清单不得因阶段放行而改写为已通过。

## 1. 目标

测试按“纯逻辑快测 → service/repository 合约 → 微信开发者工具 → 真机与上线专项”分层。M0 的自动化重点是状态、权限、版本和跨角色数据一致性；WXML、触摸、导航和设备行为必须在微信环境验证，不能由 Node 测试冒充。

## 2. 本地自动检查

在 `workspace/` 执行：

```powershell
npm run typecheck
npm test
npm run check
```

- `typecheck`：使用严格 TypeScript 配置检查小程序源码和类型声明，不生成文件。
- `test`：Vitest 单次运行。基础阶段允许零用例退出，但输出必须如实报告；开始实现领域逻辑后不再接受仅有工具链空跑。
- `check`：按 `workspace/package.json` 当前脚本执行类型、视觉契约、业务测试和后台检查，作为每次交付的最低门槛；报告应列出实际子检查结果。

依赖锁文件应提交以保证结果可重复。失败时修复原因，不通过关闭严格选项、添加大范围 `any` 或跳过测试掩盖。

## 3. 纯业务逻辑单测

测试目录建议与源码镜像放在 `workspace/tests/`。以下规则必须使用 Vitest 参数化或边界用例覆盖：

- 任务标题、内容数量、对象、开始/截止时间和字数校验。
- 任务生命周期允许和禁止的状态迁移。
- 学生任务关系与任务生命周期相互独立。
- 今日任务筛选、紧急程度排序和已完成数口径。
- 阅读/单词/习题 M0 完成条件和评分结果。
- 草稿到正式提交、版本递增、旧版本不可覆盖。
- 补交窗口、逾期标记、退回最多 2 次和 3 天重做期。
- 点评至少一种动作、退回原因必填、一键点评排除规则。
- 完成数、未完成数、待检查数和待点评数对账。
- 资源下架不影响历史任务快照。

纯逻辑测试注入 clock 和 id generator，固定时区及时间，禁止依赖当前日期或随机顺序。

## 4. Service 与 Repository 合约测试

同一组合约测试应同时运行在 M0 内存实现和后续 CloudBase 测试实现上：

- 教师只能发布到授权班级，学生只能提交本人 assignment。
- 家长只有有效绑定关系才能读取孩子任务和反馈。
- 页面传入伪造 organizationId、studentId 或 teacherId 时被拒绝。
- 发布任务原子创建快照和全部 assignment，失败不留半成品。
- 相同 operationId 重试不产生重复任务、提交或反馈。
- expectedVersion 不匹配返回 `CONFLICT`。
- command 返回后修改响应对象，不改变 repository 内部状态。
- 查询分页、筛选、排序和统计在实现间一致。
- 网络/服务失败使用统一错误码，retryable 标志正确。

场景种子增加一致性断言：三年级 2 班 36 人、既有课堂任务 27 人已提交、9 人未提交、6 人待点评，列表、详情和概览必须来自同一组记录。

## 5. 页面人工验收（M0）

### 公共登录与身份

- P-01 必填、格式、密码显隐、加载、错误保留手机号和网络重试。
- P-01 在开发者工具模拟器与真机分别点击输入框中部和图标留白区，核对光标、键盘、手机号 11 位输入以及密码特殊字符输入；若模拟器无焦点，先退出调试器元素选取模式再复测。
- M1 CloudBase 登录失败时读取 `/auth/v1/signin` 响应中的错误码，区分账号密码错误、验证码要求、账号锁定或未设置密码；排查记录不得包含请求体、密码或令牌。HTTP 400 本身不等于密码错误。
- P-02 多身份选择、单身份直达、无角色、身份不可用；不出现后台管理员。

### 教师发布

- T-01、T-05 三个固定入口均有落点。
- T-06 可选择阅读/单词/习题、增删内容、选择对象与时间、保存草稿、预览和确认发布。
- 预览不显示教师备注；发布失败保留全部表单；发布后人数和任务列表一致。

### 学生提交

- S-01 同一天存在多份课堂任务和打卡活动时，全部项目在一个区域内按退回重做、即将截止、进行中、今日打卡、其他任务排序，点击各行分别进入正确详情；完成数不计逾期/重做，休息日不出现打卡行。S-08 筛选和刷新保持状态。
- S-09 草稿、提交、失败保留、待检查、补交/重做边界可演示。
- 退回重做后先保存草稿，再在退回起 3 日内重新提交；即使原任务补交期已过仍应成功。超过重做期限只读展示并保留历史提交。
- 学生不能查看或提交他人任务。

### 教师检查点评

- T-07 任务筛选和更多操作有反馈；T-17 分组数量对账。
- 通过、评分、退回原因、逐人/一键点评的预览与二次确认正确。
- T-08 至少一种点评动作才可发布；M0 不出现可用的生产 AI 点评。

### 家长只读

- G-01、G-03、G-05 只显示当前绑定孩子，结果与学生/教师页面一致。
- 任务详情不显示可操作作答和提交；直接构造他人标识仍被 service 拒绝。

### 通用页面状态

逐页检查加载、空数据、网络失败、提交失败/点评失败、无权限、资源下架和已过期。所有主按钮、返回、筛选、弹窗确认/取消、失败重试都有明确落点；没有无说明死链。

## 6. 微信开发者工具验证

每次集成至少执行：

1. 导入 `workspace/` 并完整编译，确认 TypeScript/少量 Less 无编译错误。
2. 在 390×844 和 375×812 竖屏模拟器走通 M0 主路径。
3. 检查 Console、Network 和 Storage：无未处理异常、无敏感数据日志、场景重置符合预期。
4. 验证页面返回保持来源、筛选、滚动和未提交表单。
5. 使用弱网/断网模拟验证旧数据显示、重试和输入保留。
6. 记录开发者工具版本、基础库版本、执行日期和失败截图。

M0 主路径已验收；M1 历史遗留与 M2 新增页面须按本节记录实际开发者工具证据。M3 媒体页面还须按 `visual-design/07-handoff/page-screenshot-acceptance.md` 留存逐页效果图对照。

## 7. 真机与后续里程碑

- M0 评审前至少用一台 iOS 和一台 Android 微信真机验证登录、导航、输入、滚动、安全区和返回。
- M1 增加真实 CloudBase 权限、数据隔离、事务、弱网、幂等和回归测试。
- M1 的 S-04 必须验证页图占据主要阅读区域、高清页图失败时保留缩略图并可重试、翻页/缩放后页码与进度保持；不得把 OCR/结构化正文另行显示为主阅读内容。
- M1 的 S-02 使用虚构授权词包验证年级、教材版本、单元和关键词筛选；缺少教材字段时只显示“未标注教材”，切换词包后进度与错词按词包隔离，返回自主学习时恢复最近词包，从任务进入时不能切换。S-03 核对分类内筛选项只来自实际授权书籍，切换分类或清除筛选后可恢复结果，空结果仍可调整条件。当前演示资源不足以覆盖多教材组合时，使用本地虚构测试数据验证，不将其报告为云端真实内容验收。
- M1 的 T-06 验证开始/截止日期与时间可选择，默认截止为开始后 24 小时；截止不晚于开始时保留表单并阻止发布。发布后核对学生首页、任务列表、任务详情和家长首页均显示实际截止时间。
- T-06 同时验证 36 人单班与 68 人跨班可发布、500 人分批发布完成前学生端不可见、中断后从任务列表继续发布、501 人前端阻止且服务端返回具体 `fieldErrors`；校验失败后保留标题、内容、对象和时间，修改后可重新提交。既有非生产环境的虚构 500 人云端容量与恢复验证已纳入 2026-09-27 M2 审阅包的一次统一授权，执行时仍须按该包检查费用/配额、读取隔离和回退条件并记录实际证据。
- M1 的 S-09 阅读内容入口须打开该任务引用的 S-04 页图；首次阅读和翻页保存进度，返回任务后完成页数从已保存进度更新。未保存进度、无权限或资源异常不得凭默认页码记为已完成。
- M1 教师端复核：T-02 在超过单页容量时加载更多，班级/状态/关键词筛选与复制 CSV 内容一致；导入预检只处理本地文件，错误 CSV 不回显姓名或手机号，且不得把预检结果显示为已创建账号。T-03 编辑、停用/恢复、转班逐项核对版本冲突和撤权结果，发起任务预选当前学员。
- M1 教师任务复核：T-06 内容增删、备注不可见、草稿不生成学生任务、再次布置重新选择对象与时间；T-07 搜索/状态/日期筛选、预览、描述编辑和回收实际结果；T-17 未评分不出现演示分数，一键点评只发布统一评语且部分失败有准确反馈；待点评和已点评学生均能在 T-08 展开作业详情，已点评状态只读。详情按任务快照顺序对应本次提交的真实阅读、单词和习题汇总，缺少逐题答案或朗读音频时不显示虚构判定或播放入口。
- T-08 顶部“点评范围”列出当前教师授权的已发布任务，待点评项优先、零待点评项标注“暂无待点评”，草稿和已撤回任务不显示；当前项排第一。列表最多显示三张卡片，向下滑动可访问第四项及以后任务，不能把可见高度当作任务数量上限。入口带入任务优先选中，无有效入口时优先选有待点评提交的第一项。切换任务后班级、人数、队列和作业详情必须同步；零待点评任务显示准确空状态。班级筛选名称与人数用留白分隔，无方框或分隔符；切换班级后人数、当前条目和学生队列一致；有未发布评分或评语时切换任务/班级先确认放弃。从 T-17 直接进入单个学生详情时不显示任务或班级切换。
- M3 专项验证录音权限与已提交录音保留期、上传/转码/审核、逐题对位、播放防快进、调速/磨耳朵、跟读与点评 AI、微信订阅消息、横竖屏状态连续及弱网恢复。逐例输入、预期、证据与设备矩阵见 `docs/m3-test-baseline-2026-09-29.md`；测试基准已编写不等于这些用例已执行。

- 未修改的受保护范围及任何已知外部阻塞。
