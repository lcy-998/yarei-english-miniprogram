# M3 开源 AI 与现有小程序集成总方案（2026-10-02）

> 状态：已纳入 0.58.0 权威基线的 M3 施工方案，尚未实施或验收。本文件合并 S-05 跟读评分与 T-08 教师 AI 点评两项无外部 AI 供应商的试验路线，并说明与现有微信原生小程序、CloudBase 的接口、放行门槛及人工工作。Vosk 为已确认试验方向；Qwen3-0.6B 为已确认的首个本地可行性候选，能否进入普通云函数和正式验收仍由实测决定。M2 未退出前可完成文档、设计和本地试验，不能批量实施 M3 页面或云端功能。

## 1. 结论与适配判断

| 现有基础 | 适配方式 | 当前判断 |
| --- | --- | --- |
| 微信原生 TypeScript、WXML、Less；页面调用 service/repository | S-05 与 T-08 只处理录音、生成中、结果、编辑和错误状态，模型与策略完全放在服务端。 | **适合**。模型不进入小程序包，页面无需改框架。S-05 尚未落地，T-08 已有人工点评主流程。 |
| S-07/S-09 已以 `wx.getRecorderManager` 录制 16 kHz、单声道 MP3，并用 `wx.cloud.uploadFile` 进入私有暂存/封存 | S-05 复用录音与所有者校验思路，增加 MP3→PCM 解码及跟读任务快照校验。 | **可复用，但不是直接复制**。现有 `music-metadata` 只查格式/时长，不提供模型所需 PCM；学生首次上传、弱网与录音权限仍有 M2 验收缺口。 |
| 现有 Node.js CloudBase 云函数与服务端事务、任务快照、提交版本、`review-query` / `review-command` | Node 层负责真实身份、资源归属、次数、幂等、AI 结果版本与审计；受限推理函数只处理最小输入。 | **适合**。原点评发布继续由教师确认，不能让模型直接写正式反馈。 |
| 普通 CloudBase 函数支持 Python；项目现有 38 个函数 | Vosk 试验使用独立 Python 函数；Qwen 候选使用独立 CPU 推理函数，并先验证实际函数数量、包体与运行配置。 | **Vosk 可行性较高；Qwen 风险高**。Vosk 模型约 40 MB；候选 Qwen 量化文件约 429 MB，接近 500 MB 单版本代码包限制。 |
| 现有环境记录为个人版、未启用超额用量 | 先查当前计费周期、剩余资源点和函数配置；普通函数限量试验，不用云托管。 | 可争取**无新增支出**，不能承诺环境本身免费或未核算的调用永远零费用。云托管现需超限按量。 |

两项 AI 试验不替代 M3 的媒体审核、听力映射、防快进、微信订阅消息、原生管理工作区和正式批量导入等范围；这些切片继续按权威里程碑实施。

## 2. 端到端结构

```text
学生 S-05 ─┐
           ├─ 小程序 service / CloudBase repository ─ 已登录业务云函数（Node）
教师 T-08 ─┘                                   │
                                               ├─ 授权、发布快照、提交版本、幂等、审计
                                               ├─ Vosk 推理（内部 Python；私有 MP3→PCM）
                                               └─ Qwen 候选推理（内部 CPU；最小化证据摘要）
                                                    ↓
                                      版本化结果/建议记录（CloudBase 数据库）
```

- **客户端**不存模型、密钥、服务端评分公式、原始推理回执或其他学生的资料；只接收当前角色可见的投影。沿用已有业务会话和统一错误映射，不从页面直读数据库。
- **模型制品**不提交到小程序包或源码仓库；本地构建按锁定的文件哈希生成可复现部署包，部署后读取云端代码/模型版本核验。函数启动时不从公网下载模型，避免冷启动依赖外网与不可控流量。
- **业务入口**按当前主体、组织/班级、任务项、正式提交版本及发布快照授权。推理函数设置客户端直调拒绝；CloudBase 的函数安全规则只管客户端，内部服务端调用仍须显式限定调用身份、输入形态与资源范围。部署前先读取并合并现行环境级规则。
- **录音**沿用私有封存、受控短期读取、180 天到期停止试听和服务端清理的既定规则。真实音频不放进函数事件、客户端日志或数据库正文；音频下载地址、令牌、完整转写和学生作答正文不写日志。
- **幂等**以学生/教师、任务与提交版本、模型版本、内容哈希和操作 ID 组成稳定范围。结果附 `modelVersion`、`algorithmVersion`、状态、耗时与质量原因；权限变化或提交版本变化时旧建议失效。失败保留本地录音或教师未发布输入。

## 3. 两条能力路线

### A. 学生跟读：Vosk

1. S-05 取得当前句段/任务快照中的参考文本，录制与试听 MP3，私有上传后由 Node 入口再次校验本人、录音哈希、文本版本、有效次数和提交轮次；客户端给出的文本或分数不可信。
2. 内部 Python 函数将 MP3 转为 16 kHz 单声道 PCM，Vosk 返回词、时间与识别置信度；领域模块按参考文本顺序对齐。试验性完整度取有效覆盖、流利度取停顿与语速，发音分只使用可解释的**清晰度代理指标**，不能宣称音素级发音质量。
3. 返回 0—100 总分及发音/流利度/完整度三项，并明确标为“试验性评分”。静音、严重噪声、截断或低置信度显示“暂无法可靠评分”；15 秒超时自动重试一次，失败保留录音，无效尝试不占五次有效上限。
4. 试验结果先与提交版本关联，**不计正式任务成绩或打卡 AI 分**。教师仅按当前授权试听和查看原始维度；人工覆盖正式分须填原因并保留原始结果。正式放行前用合规儿童朗读样本与人工分盲评，核对有效录音评分成功率 ≥95%、时延、明显误判、设备与弱网。

### B. 教师点评：Qwen 小模型候选

1. T-08 点击“AI 点评”后，服务端从 `review-query` 同一授权来源取得当前正式提交与冻结任务内容，投影为去姓名、手机号、学号、录音和无关资料的最小事实摘要；学生答案文本被视为不可信数据。
2. 候选 Qwen3-0.6B 量化 GGUF 在本地 CPU 先做质量、包体、内存、冷启动与中文生成试验。只在普通 CloudBase 函数可容纳、套餐内预算可测且输出质量过门槛时部署。模型文件/推理程序固定版本与 SHA-256，不在运行时下载或调外部 AI API。
3. 建议须为 50—150 字中文，最多重新生成 3 次。服务端校验事实引用、长度、敏感内容与提交版本；虚构分数、跨学生信息、攻击性或不当建议均拒绝展示。模型不可用时，教师照常手工点评；规则化常用评语只能标作推荐，不能冒称 AI 建议。
4. 教师可采纳、编辑、放弃；正式发布继续走 `review-command` 的版本/权限校验与确认。AI 从不直接发布、评分或退回。针对一人的个性化建议不能绕过 T-17 批量评语预览，自动套用给其他学生。

## 6. 风险、回退和剩余 M3 范围

1. **Vosk 质量/时延失败**：保留录音与人工评价，试验分不计成绩；复盘儿童样本、设备与句长。不能通过修改分数阈值或缩短已确认的 5 分钟录音上限伪造通过。
2. **Qwen 包体/CPU/费用失败**：停止云端模型试验，保留人工点评与明确标识的规则推荐；TCH-007 的 AI 切片继续记为未通过。CloudBase 云托管需超限按量，本零新增费用路线不自动转入。
3. **安全/事实错误**：关闭对应功能开关，回退精确函数版本；历史任务、提交、点评和审计不删除。试验结果与正式反馈分维度存储，不能把模型输出直接写成学生成绩或家长可见点评。
4. **M3 总体范围**：本方案只解决两条 AI 路线。媒体生产/审核、题目音频对位、防快进、订阅消息、A-01—A-08 原生管理和教师正式批量导入仍须按当前 0.56.0 基线分别实施与验收，不能因 AI 试验进展提前宣称 M3 完成。
