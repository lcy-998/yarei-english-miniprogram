# 自主跟读评分等待无返回：云端排查与修复

日期：2026-10-25。沿用 0.128.0 产品基线，属于既有自主即时评分能力的缺陷修复。

## 排查结论

1. 既有非生产虚构组织近期有 4 条自主录音停在 processing、dispatchState=sent、workerInvocationCount=0，其中 3 条为当天录音。另有多条 invalidated 终态，不是模型低置信度。
2. 评分命令函数已更新，但 worker 的学习资源适配器仍为旧实现。同一批 8 条云端记录的当前身份与授权版本均有效；当前源码的 source 校验为 true、字段差异为空，下载的旧 worker 源码对相同数据返回 NOT_FOUND。旧 worker 因此在推理前误拒有效自主阅读资源。
3. 原异步派发未明确 Qualifier。修复权限后，不指定版本的合成样本仍在观察窗口内未领取；直接同步调用同一云端 worker 可以返回 94 分。随后用官方 SDK 明确指定 `$LATEST` 的 Event 被领取；在项目 transport 中给 Event 请求明确版本后，第二份合成样本不依赖同步补跑，约 9.513 秒完成异步评分。此为已观测的修复证据，不据此推断腾讯云内部队列实现或承诺所有音频都在该时间内完成。官方接口版本参数说明见 [腾讯云 Invoke](https://cloud.tencent.com/document/api/583/17243)。
4. 已部署的旧查询函数还会返回自主评分历史；本地已有的不留历史规则此前未同步。此次同步后，自主 getScore 仍可返回本次结果，listAttempts 返回空数组，作品记录不带历史分数。
5. 客户端查询一旦失败就停止轮询，且评分重试先清空 scoreView 再读版本号，可能错误使用最初封存版本。这两处在主包内嵌控制器与学生分包控制器中同步修正：可重试查询故障继续退避轮询，权限等不可重试故障不自动重复；重试请求使用清空视图前的当前版本。

## 实际验证

- 当前源码连接真实非生产数据库进行身份、资源、录音创建、私有上传、格式封存、作业受理与派发；worker 与 Vosk 推理均在 CloudBase 实际执行，没有本地模型推理。
- 两份测试录音使用归档原创合成样本，字节数与 SHA-256 对照清单。第一份因验证脚本参数顺序错误，在评分受理前停止，修正脚本后复用同一封存录音；其后同步诊断得到 94 分。第二份用明确版本的 Event 自动返回 94 分（发音 100、流利度 74、完整度 100），从创建到读取终态约 9.513 秒；worker 仅领取一次。
- 通过既有作业服务对虚构学生卡住的记录执行受控幂等重派，保留原录音与原评分操作号。当天 3 条最终均 scored；10 月 22 日的一条返回 unreliable/NO_SPEECH。已 invalidated 的旧记录未强制重置或改写分数，用户可重新录制。
- 最后使用下载的新查询代码连接同一云端数据库读回：合成样本 scored/94，自主历史尝试数 0，作品记录存在但不包含分数；该虚构学生 processing 数为 0。
- 后端跟读及保留期测试 13 文件 52 项通过；明确版本派发变更后 transport 与异步作业定向 13 项通过。小程序最终处理恢复、网络重试、录音上传、内嵌自主重录 4 文件 12 项通过。前后端 TypeScript 检查通过。

没有重跑全量 workspace 检查；先前未修改的教师评分草稿共享测试失败仍按原记录保留。未通过已登录小程序页面或真机完整操作，不把服务层身份构造及直接调用当作真实登录页面验收。本轮没有正式发布小程序；客户端轮询与重试修复须使用最新代码预览。合成短音频的成功不代表儿童语音质量、长录音性能或正式 AI 成绩验收。
