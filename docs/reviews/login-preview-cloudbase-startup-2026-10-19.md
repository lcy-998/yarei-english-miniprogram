# 小程序预览登录与验证码启动故障修复（2026-10-19）

## 现象与原因

- 开发者工具模拟器和此前的预览显示演示登录行为：内存账号 `13800000001` 可用演示密码登录，找回密码页成功请求时会提示固定演示码。
- 本机还有一个使用相同 AppID 的历史工程 `D:\app\workspace-admin-session`，其启动逻辑在云端初始化失败时退回内存仓库，容易与当前 `D:\app\workspace` 混淆。
- 对当前工程的真实模拟器重新编译、清缓存并启动后，仍复现内存演示会话。根因是小程序构建后的 `@cloudbase/js-sdk/app` 导出为带 `cloudbase` 字段的包装对象；客户端加载器将包装对象直接传给认证注册，触发 `registerComponent is not a function`。异常发生在仓库激活之前，默认内存仓库继续工作。

## 修复

- `installed-js-sdk.ts` 从小程序包的 `cloudbase` 导出取得实际 SDK 核心，验证 `init` 与 `registerComponent` 后再注册认证和云函数能力。
- `app.ts` 捕获 SDK 加载失败并阻断仓库启动，不再让加载异常静默保留内存登录路径。
- 增加包装导出选择和 SDK 加载失败的定向测试。

## 实际验证

- `D:\app\workspace` 的 TypeScript 类型检查通过；SDK 与启动定向测试 8/8 通过。
- 微信开发者工具 2.02.2609231 以明确项目路径编译并生成预览包，AppID 为项目配置中的 `wx6881cb67e05b1bd1`。
- 当前工程模拟器登录页加载新的 WebP 吉祥物；重新启动后重复调用启动检查输出 `CloudBase repository active`。
- 删除本轮测试产生的内存演示会话后，用内存专属虚构账号尝试登录，留在登录页并返回“手机号或密码不正确”，没有再生成内存演示会话。

## 尚未验证

- 没有可接收短信的测试手机号及其验证码，因此未实际发送或接收短信；CloudBase Auth SDK 的验证码能力已在启动时注册并通过能力检查，但短信供应商配置、额度和送达率不由模拟器登录试验证明。
- 未取得用户现用非生产账号的密码，不将内存演示账号失败视为该账号已成功登录。真机扫描新预览码后的本人账号登录和短信送达仍待该账号持有人执行。
