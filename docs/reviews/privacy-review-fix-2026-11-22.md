# 0.129.0 手机号隐私审核修复

## 问题与范围

用户确认微信退回的是 0.128.0，要求增加用户服务协议、隐私政策，明确手机号用途、方式并在收集前主动同意。用户于本次会话提供个人主体完整姓名和公开联系电话，已写入 `workspace/miniprogram/legal/legal-config.ts`；身份证号不收集、不写入工程。

此版本只修改小程序入口、协议展示和同意流程。阿里云服务、原业务数据与英语资产不改动。产品基线升至 0.129.0；后端 healthz 仍显示其原数据迁移版本 0.128.0，两者含义不同。

## 实现

- 主包 `pages/legal/document/document?kind=service` 与 `?kind=privacy`，登录前和“我的”均可打开，正文可滚动及选择复制。
- 登录和找回密码页面均默认未勾选，同意前输入控件禁用，输入事件及发送请求的方法均再次校验。
- 阅读链接不会自动同意；取消同意清空手机号、密码和找回密码验证状态；新打开页面不会继承其他使用者的同意。请求进行中锁定表单和同意状态。
- 文本按当前阿里云实现说明手机号手动输入、HTTPS、账号验证、录音/视频、教学关系、权限、数据保留及联系渠道；不声称短信找回密码已开通，也不将媒体隔离等同于物理销毁。原 CloudBase 保留副本如实披露。
- 微信系统隐私授权维持平台原生弹窗。新增查看平台隐私保护指引的入口，兼容 API 缺失或未配置错误；不通过点击协议链接代替平台授权。
- 文本就绪标志与空信息校验可阻止缺少主体/联系渠道的构建收集表单信息。正式源码中的信息来自用户本次明确提供的公开资料。

- `npm run check`：类型、视觉静态契约、354 文件 1545 个主工程测试、11 文件 49 个管理端测试及管理端构建通过。原管理端 bundle 体积警告仍在。
- 新增 8 个针对性行为测试覆盖默认拒绝、正常提交、取消清空、重新进入、请求中重复操作、找回密码绕过、链接不代表同意与文本必需信息。
- 调整组件 CSS 标签选择器及文本复制属性后，再次执行 typecheck、visual:check、上述 8 个测试通过。
- 微信开发者工具实际编译并显示两份完整协议，主体及联系渠道正确，隐私政策可滚动至末尾；返回登录仍未勾选。点击登录或获取验证码会显示“请先阅读并同意…”；无编译错误。未以用户身份代为勾选法律协议；勾选后的请求路径通过自动化测试验证。
