# 教师 AI 点评“测试任务”不可用诊断与修复（2026-10-22）

## 结论

既有“测试任务”自动建议记录状态为 `failed`，历史失败原因只保存为 `unsafe_output`，没有保留具体子规则，也未保存被拒绝的候选文案，因此不能从旧记录反推出唯一触发项。

随后对同一虚构任务的当前提交事实做了非生产、无落库推理复现。复现先后观察到：

- v11 输出偶发缺少服务端认可的动作词；
- 输出偶发包含内部编号/字段，或不受证据支持的质量表述；
- v12 的结构化引用要求又偶发产生空引用或推理超时。

最终将模型输入中的任务内部 ID 移除，由服务端只在评语包含事实原文锚点时回填对应引用 ID；同时缩短并明确学生可见文案规则、扩充仍具明确动作含义的动作词校验。未放宽事实锚点、长度、引用有效性、敏感字段或无依据成绩表述等拒绝条件。

同一任务事实经 v13 再测，输出通过长度、动作词、事实锚点、引用映射及安全内容检查，推理耗时约 58.7 秒。原学生作答和生成文案未写入报告、函数日志或数据库；探针没有写入 AI 建议记录、点评或成绩。

## 修复内容

- `teacher-v13` 模型提示要求 55—90 个汉字、引用具体证据原文，并写出明确可执行的下一步；模型不再接收题目/词条内部 ID。
- 推理端依据评语中实际出现的原文锚点映射引用 ID。没有匹配锚点仍拒绝结果。
- 输出上限调整为 160 token；服务端动作词列表增加“圈出、区分、抄写、跟读、排序、配对”等具体行为词，不接受空泛建议。
- `review-command` 发布门同步到 `teacher-v13`，旧版本与新建议版本保持校验一致。
- 非生产部署只更新教师建议推理、教师建议命令、后台 worker、提交命令的提示词版本，以及 `review-command` 的提示词版本门和 worker 的动作词规则。函数保持 `$LATEST` 路由；没有改集合、权限、业务记录、定时器或触发器。

## 验证与回退

- 非生产环境只读预检：NORMAL 个人版、未付费、超额计费关闭、计费读数 0；函数调用配额读数 7,002（低于项目 190,000 停止线）。
- 部署后五只相关函数均为 Active，路由为 `$LATEST`，无额外权重；依赖安装为 FALSE。推理运行配置仍为 Python 3.11 / 1024 MB / 210 秒，其他函数运行配置读回未变。
- 本地教师 AI 服务和 task-core 定向测试 141/141 通过；CloudBase TypeScript 类型检查通过；推理 Python 源码语法检查通过。
- 部署前发布了 inference、worker、review-command 的不可变回退版本；本机保留部署前函数包。模型与 llama.cpp 的 SHA-256 与已批准制品清单相同。
- 没有完成已登录微信开发者工具中的教师页面采纳/发布闭环；桌面会话未提供可操作的本机应用窗口。旧自动建议记录仍是历史失败状态；教师需在该提交上点“手动生成”以创建新的建议操作，不能由旧幂等失败操作自动重跑。

本次仅处理既有虚构“测试任务”和已核对的非生产 CloudBase 环境；没有改生产内容、真实成绩或正式点评。
