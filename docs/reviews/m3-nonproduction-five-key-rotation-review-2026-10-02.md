## 对象、预检与一次授权范围

- 唯一既有非生产个人版环境，**仅虚构账号**；现行 38 只 Node 函数均在部署启动时读取全部六项环境变量。首批保持主体 pepper 不变，拟替换 `YAREI_QUERY_CURSOR_SIGNING_KEY`、`YAREI_BATCH_REVIEW_SIGNING_KEY`、`YAREI_BINDING_CODE_DERIVATION_KEY`、`YAREI_BINDING_CODE_PEPPER`、`YAREI_BUSINESS_SESSION_ENCRYPTION_KEY` 五项。旧 M1/M2 数据、身份关系及提交不得删除；不碰生产、真实账号或付费开通。
- **执行前必须**核对当前计费周期剩余函数调用/计算、部署版本、存储与流量额度及无超限费用；取得短维护窗口、现行 38 只函数的完整配置**键集**与非空状态备份、`$LATEST`/不可变版本/流量路由、各函数代码哈希和 IAM 操作权限。只在受限保管位置保存实际新旧值；审阅/执行日志只记字段名、密钥版本号及不可逆哈希摘要。任一余额、权限、完整键集或路由无法核实即停。
- 当前 CLI 为 `@cloudbase/cli` **3.8.2**。[官方文档](https://docs.cloudbase.net/cli-v1/functions/configs)说明 `envVariables` 在新版本可选择 merge/overwrite，旧版会覆盖整份；实际执行命令及在线配置仍须先以只读差异核对，禁止以仅五键的配置覆盖其他环境变量。所有新旧版本都可能带密钥配置；[不可变版本包含环境变量](https://docs.cloudbase.net/cloud-function/gray-release)，回退旧版本可能重新启用暴露值。

| 2. 批量点评签名 | `review-query` 与 `review-command` | 旧待确认预览令牌失效；教师须重新预览，再发布一次。检查已发布反馈不重复、不覆盖人工分。 |
| 3. 绑定码两键同批 | `relationship-command` | `YAREI_BINDING_CODE_DERIVATION_KEY` 与 `YAREI_BINDING_CODE_PEPPER` 同批改。旧未使用码不可再验，虚构演示人员需重新签发；已建立的家长孩子关系不删除。验证新码单次使用、旧码拒绝及错误 5 次作废。 |

每批功能性函数同步后，仍须把**其余现行函数**配置中的该项旧副本清除；只有 38 只 `$LATEST` 的配置和正在接流量的版本都已使用新版本，才把该项记作完成。新建语音 Node 函数尚未在云端，不属于这 38 只；将来仅用新键部署。

## 执行记录、恢复及停止条件

1. 用户对本具体非生产五键包、短维护窗口、零新增费用及下述回退范围明确授权后，由有权限人员生成新值并只在服务端受限配置中更新。每批先核对旧/新字段集合差异和路由，再按函数顺序更新；记录函数名、版本、代码哈希、配置键名/非空、密钥版本哈希、`Active` 状态与开始/结束时间，不输出值。
2. 每批用虚构学生、家长、教师和管理员走登录/本人数据、绑定关系、任务与提交、授权班级点评、后台审计。重测跨组织拒绝、撤权旧会话、旧游标/旧预览失效、绑定码新旧口径及幂等一次写入。全部函数及版本路由无旧值副本、没有费用或额度警报后进入下一批。
3. 安全恢复优先**暂停受影响入口、保留输入与记录、使用新值修复配置并前滚**。旧不可变版本仅作受限取证；把流量回到旧版本会重新使用已暴露密钥，不能作为正常“安全回退”。若业务连续性要求紧急短时旧值回退，必须另行风险确认，明确持续暴露、限定时间并随后再次轮换。
4. 任一函数 `Active` 下降、旧/新值混用造成业务失败、配置中无关键被误删、越权或跨组织通过、重复点评/绑定、费用警报、剩余额度不足、旧版本仍接流量或四角色不能重新登录，立即停止后续批次并执行第 3 步；不修改 `YAREI_SUBJECT_PEPPER` 试图绕过故障。

首批没有触碰身份摘要索引，因此本地纯逻辑模拟可验证令牌、游标、批量预览与旧绑定码会因换键失效；相关测试在 `workspace/m1-cloudbase/tests/runtime/key-rotation-readiness.test.ts`。实际 38 只函数配置/路由和 CloudBase 计费仍须执行前只读核对，当前无云端轮换证据。
