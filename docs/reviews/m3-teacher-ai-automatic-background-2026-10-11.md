# M3 教师 AI 点评后台默认生成施工与验证（2026-10-11）

## 决定与范围

用户确认学生**正式提交后排队**生成一次 AI 点评建议。教师可离开 T-08，之后查看状态和建议；只有教师采纳、编辑并确认发布后才形成学生可见反馈。草稿、旧提交版本不触发。继续沿用 Qwen3-0.6B 非生产试验与人工点评回退路径；本次未开放生产 AI。

权威基线为 `0.91.0`，见根目录两份权威文档和 `DOCUMENTATION.md`。

## 实现

- `submission-command` 在正式提交事务成功后投递签名 SCF Event。重复提交使用同一业务操作，后台建议使用组织与提交 ID 导出的稳定操作 ID；建议存储的原子预留避免重复推理。派发错误不撤销学生已经成功的提交，教师仍可人工点评。
- 新增私有 `teacher-suggestion-worker`，客户端调用规则为 `invoke:false`，服务端另以 60 秒窗口 HMAC 验签。worker 从当前任务创建教师的有效角色与授权、任务快照和当前提交提取最少事实，完成前后再次核对授权和版本。教师查询也重新鉴权；同班其他当前有权教师可获得仅绑定自己的同源建议副本，以便按原点评服务完成确认发布。
- T-08 打开提交时自动查询，显示排队、处理中、完成或失败；处理中可离页并继续人工批阅。建议不会自动填入评语；“采纳到评语”明确点击后才填入，仍需正式发布。
- 对无客观对错判定的题，只向模型投影“已有作答、待教师核对、尚无对错判定”，不再提供互相抵触的“没有判定错误/正确”。新生成内容拒绝“无错误与正确”等明显生硬表述。

## 实际验证

- 本地后端最终 `npm run check`：172 个测试文件、896 项通过；小程序根最近一次 `npm run check`：321 个测试文件、1377 项通过，历史网页后台 49 项、类型检查与构建通过。根检查之后新增一项授权教师副本测试，定向通过；一次并行运行时非本任务素材导入测试因 5 秒超时失败，随后单测和独立完整后端检查均通过。
- 第一份虚构提交发现派发层用业务提交 ID 直接取数据库文档，但文档键还包含组织前缀，故后台任务未生成；修为按业务 ID 精确查询且只接受唯一、已提交记录后复测。
- 第二份虚构提交：学生正式提交及同操作重放为同一提交 ID，学生读取建议被拒绝，教师首次查询为 `processing`；约 132 秒后得 53 字试验建议，生成次数 1、可再生成 3 次，教师正式反馈仍为空。微信开发者工具 T-08 实际打开后自动显示该建议，评语输入在教师点击“采纳到评语”前为空，点击后才填入。该样本含生硬文案，未计内容质量通过。
- 调整事实投影后第三份虚构提交再次自动进入 `processing`，云端保存 62 字 `trial` 建议，教师重新登录后授权查询为 `trial` 且需确认，正式反馈为空。轮询中一次客户端 `fetch failed`，后台任务仍完成并可恢复查询。教师随后把建议改写成事实谨慎的文字并通过正常点评命令发布；云数据库读回 1 条反馈，分数 0、AI 建议 ID、模型与 `teacher-v6` 提示词版本、`teacherEditedText=true`。教师发布后再查自动建议因分配关系版本变化返回 `CONFLICT`，符合旧建议不可继续使用的边界。
- 第三份模型原文仍有重复、表达生硬；它是可编辑试验建议，不能据此判定 AI 文案质量达标。百份双人质评、长时/大量并发与真机弱网仍未验收。
- 虚构学生从客户端直调私有后台函数被平台以 `EXCEED_AUTHORITY` 拒绝；管理端无签名事件由函数返回 `forbidden`，未触发模型。
- 本任务创建并独立使用的首份故障复现任务及第三份闭环任务已按确切任务 ID 软回收，教师活动列表不再显示，提交、点评与审计历史保留。第二份任务在共享环境中被另一测试流程点评，本任务未再改动该任务。

## 当前结论

“提交后后台默认生成 → 教师离页恢复查看 → 教师采纳或编辑并发布”的**非生产功能闭环已通过**。模型文案质量和约两分钟等待仍未达到正式放行门槛，继续标为 M3 试验能力。生产环境未更新。
