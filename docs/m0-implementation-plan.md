# M0 实施计划

## 1. 目标与退出条件

M0 只验证一条纵向闭环：

`P-01/P-02 → T-01/T-05/T-06 发布任务 → S-01/S-08/S-09 提交 → T-07/T-17/T-08 人工点评 → G-01/G-03/G-05 查看结果`

退出条件以权威产品文档为准：主路径可点击、前后数据一致、成功/失败/空状态可演示、无死链，并完成至少一次教师和家长评审。M0 不接真实后端、AI、媒体处理或订阅消息。

## 2. 实施顺序

### 步骤 0：工程基线

- 输入：现有微信模板、权威文档、技术架构。
- 输出：Git 忽略规则、项目说明、类型检查和测试命令、技术文档。
- 文件所有权：根目录工程文档，`workspace/package.json`、`workspace/tsconfig.json`。
- 退出条件：依赖可安装，`npm run check` 成功，微信项目配置和模板页面未被改写。

### 步骤 1：领域模型与通用结果

- 输入：`docs/data-model.md`、权威状态机和业务规则。
- 输出：领域类型、状态联合类型、标识/时间约定、`Result`/错误结构、纯校验函数。
- 文件所有权：`miniprogram/domain/`、`miniprogram/shared/`、对应 `tests/domain/`。
- 退出条件：任务状态、学生任务关系、提交版本和点评分别建模；校验与状态流转单测通过；领域代码不依赖 `wx`。

### 步骤 2：Service 合约和内存 Repository

- 输入：`docs/service-contracts.md`、领域模型。
- 输出：service 接口、repository 接口、内存状态树、service 容器和实现选择工厂。
- 文件所有权：`miniprogram/services/`、`miniprogram/repositories/`、`tests/services/`。
- 退出条件：页面只能通过 service 操作数据；返回值为拷贝；非法权限、非法状态和重复写入有测试；未来可换 CloudBase 实现而不改页面调用。

### 步骤 3：统一演示数据和场景

- 输入：权威文档第 10.7 节统一演示数据、场景要求。
- 输出：学校、班级、虚构用户、任务、资源、提交、点评种子；正常/空/失败/无权限/下架/过期等场景。
- 文件所有权：`miniprogram/mocks/`、`tests/mocks/`。
- 退出条件：三年级 2 班人数、提交人数、待点评人数等统计与详情可自动对账；模拟数据无真实个人信息；场景切换不进入正式 UI。

### 步骤 4：公共登录与身份

- 输入：P-01、P-02 规格，模拟账号/角色服务。
- 输出：模拟登录、错误保留手机号、多身份选择、单身份直达、角色会话和返回逻辑。
- 文件所有权：公共页面目录、`session/`、公共表单/状态组件。
- 退出条件：学生、家长、教师均能进入正确首页；后台管理员不显示；加载、失败、无角色和身份不可用可演示。

### 步骤 5：教师发布任务

- 输入：T-01、T-05、T-06 规格，阅读/单词/习题模拟资源。
- 输出：工作台入口、任务中心、课堂任务表单、资源增删、对象/时间/描述/备注、草稿、预览和确认发布。
- 文件所有权：教师工作台/任务中心/布置任务页面及仅供其使用的组件。
- 退出条件：必填和时间校验正确；预览不显示教师备注；发布失败保留表单；发布后生成任务快照和 36 个学生任务关系，并可在检查列表查询。

### 步骤 6：学生查看与提交

- 输入：S-01、S-08、S-09 规格，已发布任务。
- 输出：今日任务摘要、筛选列表、任务详情、阅读/单词/习题的 M0 模拟作答、草稿保存和提交。
- 文件所有权：学生首页/任务列表/任务详情及作答子组件。
- 退出条件：学生只能操作本人任务；提交失败保留作答；成功后新增不可变提交版本并进入待检查；教师端完成数和待检查数同步变化。

### 步骤 7：教师检查与人工点评

- 输入：T-07、T-17、T-08 规格，学生提交。
- 输出：任务筛选、学生分组、逐人通过/评分/退回、文本/评分点评、一键点评预览与确认、历史版本入口。
- 文件所有权：教师检查列表/完成情况/快速点评页面及点评组件。
- 退出条件：未完成和已点评学生不能被批量覆盖；至少一种点评动作才可发布；失败保留输入；点评后学生关系、提交审核结果和反馈记录同步更新。

### 步骤 8：家长只读查看

- 输入：G-01、G-03、G-05 规格，已点评提交与家长绑定关系。
- 输出：当前孩子概览、孩子任务列表、只读任务详情、反馈详情和来源返回。
- 文件所有权：家长首页/孩子任务/反馈详情页面；只读复用组件。
- 退出条件：只能读取绑定孩子；所有作答/提交/修改操作不可用且 service 仍强制拒绝；评分、点评、版本和教师端一致。

### 步骤 9：异常状态与主路径联调

- 输入：全部 M0 页面、场景服务和测试矩阵。
- 输出：加载、空数据、网络失败、提交失败、点评失败、无权限、下架、过期的可演示状态；稳定的返回路径和表单保留。
- 文件所有权：各页面状态映射、共享状态组件、service 错误映射、端到端验收记录。
- 退出条件：每个主按钮有落点和反馈，无说明死链为零；统计自动对账；`npm run check`、开发者工具编译和 M0 人工主路径均通过。

### 步骤 10：教师与家长评审

- 输入：可运行原型、演示账号/场景说明、评审脚本。
- 输出：教师和家长各一次评审记录，含完成率、误触、返回路径、创建/点评耗时及问题等级。
- 文件所有权：`docs/reviews/` 下的评审记录和必要的权威文档变更。
- 退出条件：严重阻塞问题关闭；产品负责人确认达到 M0 退出条件后，才开始 M1。

## 3. 文件协作边界

- 基础设施任务优先拥有 `domain/`、`services/`、`repositories/`、`mocks/` 和测试；页面任务不在这些目录内复制规则。
- 每个页面任务只修改其页面目录和已明确分配的共享组件；共享组件改动先确认消费者，避免并行覆盖。
- `app.json` 路由由单一集成任务集中修改，避免多个页面任务并发改同一文件。
- 每一步先同步主分支当前改动并检查工作区，不覆盖其他任务未提交文件。

## 4. 每步通用完成定义

- 权威范围未扩大，页面编号和文案口径可追溯。
- 新业务规则有 Vitest 用例；TypeScript 严格检查通过。
- 写操作具备加载、成功、失败和防重复状态；失败不丢输入。
- 权限同时在视图和 service 层验证。
- 不含真实个人数据、服务端密钥或生产资源。
- 实际运行过的验证有记录；未执行的开发者工具或真机验证明确列出。
