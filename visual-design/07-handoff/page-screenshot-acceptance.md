# 开发后逐页效果图对照验收方法

> 适用所有已批准页面，M3 先执行 S-04、S-05、S-07、S-09、T-08、T-19、T-20、A-08。只用 `04-pages/current/<ID>.png` 作为正常态主稿；T-19/A-08 待审批期间不得开启其正式页面样式验收。

## 1. 每页建立同一份对照记录

| 字段 | 必填内容 |
| --- | --- |
| 基线 | 页面 ID、`current` 文件相对路径与 SHA-256、台账批准日期、组件板/状态板/响应式稿版本、设计令牌版本。 |
| 运行条件 | Git 提交或工作树标识、测试数据/角色、微信开发者工具与基础库版本或浏览器版本、系统/设备、视口、方向、字体倍率、网络条件、时间。 |
| 证据 | 原始运行截图、对应主稿、同尺寸并排图或半透明叠图、状态截图、操作录屏/日志摘要；动态数字与系统状态栏单列说明。不得改动原始截图。 |
| 结论 | 每项通过/失败/未测、差异位置和严重度、修复责任、复测证据、审批人及日期。未测不得写通过。 |

截图命名建议：`<ID>-<state>-<viewport>-<orientation>-<device>-<date>.png`；证据放 `output/visual-qa/<date>/`，记录表放 `docs/reviews/`。截图仅使用虚构数据，不包含口令、令牌或真实个人信息。

## 2. 对照顺序与判定

1. **准入**：先核对里程碑、页面台账和 `current` 主稿；未批准页面只做候选审阅。检查运行页面使用公共令牌、组件和 `03-assets/production/` 所列素材，效果图 PNG 不进入程序包。
2. **尺寸和安全区**：小程序 390×844 主视口、375×812 补充视口；后台 1440×900 主视口、1280×800 与 768×1024 补充视口。记录物理截图与 CSS/逻辑视口的缩放因子；安全区、胶囊、底部手势区、主操作和滚动末端必须可达。按相同内容区边界对齐后再比较，不裁掉溢出区域。
3. **颜色和排版**：按 `design-token-contract.md` 查主色、状态色、暖白表面、边框、阴影、字号/行高/字重、20px 小程序页边距或后台 24–32px 边距、卡片内边距和圆角。颜色以令牌和浏览器/微信计算样式核对，不从压缩后的效果图取色；文字放大 200% 时可纵向增长，不能遮挡或截断关键操作。
4. **组件与素材**：逐项核对导航、按钮、输入、筛选、卡片、列表、抽屉、Toast、播放器、录音控件的尺寸、图标隐喻、状态文字和焦点/按下反馈。Logo/吉祥物保持比例；页图以 `contain` 或可缩放容器展示，环境图仅裁装饰边缘。不得从主稿裁出文字、按钮或波形当素材。
5. **叠图**：把运行截图映射到主稿的内容矩形，做 50% 透明叠图并并排保留原图。只遮蔽时间、系统状态、演示数据中确实可变的字段；不得遮蔽布局、操作、错误或状态。记录偏差的坐标、预期/实测和像素或百分比；自动像素差只作定位辅助，不代替人工审阅。
6. **状态和交互**：正常态后逐项检查加载、空、错误、无权限、下架、禁用、录音拒绝/已录制/上传失败、AI 生成/失败/低置信度、转码/审核/映射、防快进。点击主操作、返回、筛选、保存、取消、重试，核对操作落点与输入/录音保留。页面的权限与业务结果按权威规格验证，不能只靠图像相似判通过。
7. **响应式**：小程序 844×390/812×375 横屏与旋转往返，后台 768×1024/1024×768 平板；使用 `06-responsive/` 补充稿核对双栏/三栏、抽屉与表格滚动。旋转前后比对页码、题号、答案、录音、播放位置、倍速、磨耳朵、任务连续进度及筛选；键盘弹出后仍能到达提交/退出动作。

判定为阻断：主操作不可达、内容或安全区遮挡、关键字段/状态缺失、未经批准页面样式进入代码、业务图片被裁切、状态误导、输入/录音丢失、权限越界。纯装饰偏差可记录为一般差异，但必须给出是否接受与复测证据。页面结论只能在正常态、必需状态、目标视口和关键交互均有证据后写“通过”。
